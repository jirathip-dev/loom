# loom

One Cargo workspace: the engine crates in `crates/loom-*`, plus `xtask/`. The decisions are
`docs/decisions/`; the architecture is `docs/architecture/`. loom is game-blind: a game depends on it, never
the reverse.

## The one gate

`cargo xtask check` runs `./.gatekeeper/run check`, the same command CI runs; it passes its arguments on
(`cargo xtask check --gate rust/clippy`). Run it before every push.

- A gate of our own is one file in `.gatekeeper/gates/`. `.github/workflows/ci.yml` only calls gatekeeper.
- gatekeeper's pin (`.gatekeeper/config.toml`, `.gatekeeper/run`, the `uses:` line) changes only through
  `./.gatekeeper/run pin <version>`.
- `.drover/arch.toml` holds the frozen files, the one-file-an-entry folders, the bans and the file size limit.

## Toolchain

`mise.toml` pins Rust 1.100, `cargo-nextest` and `sccache`. Dev builds use `opt-level = 1` for our crates and
`3` for dependencies.

## Rules

- Every crate root starts with `#![forbid(unsafe_code)]` (R5, `docs/architecture/crates.md`).
- A new crate is a folder under `crates/`; the workspace finds it by glob.
- `xtask` links no workspace crate; it starts processes.
- A new dependency is the maintainers' call first, then a line in `.gatekeeper/deps.toml`.
- `Cargo.lock` is generated by `ci/lock`, on a conflict too, and never merged by hand.
- A determinism rule (D1 to D9) or crate rule (R4 to R7, R10) changes only with its enforcer.
- This repo is public. Its files, issues, pull requests and commits speak of "a game" and never name one. No
  game data or kept images: `.drover/rules.md` fails a `.ron` or `.png` file.
- CI runs on GitHub's hosted runners only: `arch.toml` bans `self-hosted` and `pull_request_target`.
